# OpenAPI-derived MCP server

**Date:** 26 November 2026
**Author:** garethhaagman
**Type:** feature

## Description of change

Wire now ships a Rust MCP server under `apps/mcp`. Every tool comes from an operation in the committed OpenAPI spec. Controllers declare snake_case `operationId` values and summaries so agents get stable tool names. CI fails when the tool snapshot drifts from the spec.

## Implementation details

- `apps/mcp`, thin wrapper around `rmcp-openapi` that embeds `internal-docs/api/openapi.yaml`, serves stdio or streamable HTTP, and signs in with Better Auth
- `apps/mcp/tools.snapshot.json` plus `wire-mcp check` / `generate`, CI job for rustfmt, clippy, tests, and OpenAPI drift
- `@ApiOperation({ operationId, summary })` on every HTTP handler, enforced by `wire-api/require-api-operation`
- `@ExcludeFromMcp()` (`x-wire-mcp.exclude`) for streams and raw byte routes agents cannot call as JSON tools
- `declarePathParameters` in OpenAPI export so path params taken via `@CurrentActor()` still appear in the spec
- `make dev` starts MCP on `http://127.0.0.1:3002/mcp` with the seeded `dev@wire.local` credentials

## Trade-offs

- **Chosen:** `rmcp-openapi` library that loads the spec at runtime. One tool per operation, no generated stub tree to own. Matches Wire's "parity from OpenAPI" docs.
- **Rejected:** `openapi-mcp-generator` / `mcpify` codegen that emits a full TypeScript or Rust project. Regenerating overwrites custom Wire glue (auth cookie, envelope unwrap, workspace default).
- **Rejected:** Hand-authored MCP tools in TypeScript. Every API change would need a second manual mapping and would drift from OpenAPI.
- **Rejected:** `mcpify`'s three meta-tools (`search` / `get` / `call`). Wire's MCP docs list named tools per operation, not a generic caller.
